A BOARD FOR YOUR CODING AGENTS

Every coding-agent session on your machine: found, sorted, resumable.

agent-eye keeps a local list of every session, shows where each one stands and what needs you, and puts you back in it with one key. Works with Claude Code and Codex CLI, built for more agents.

INSTALL TRY THE DEMO
brew install maxipavlovic/tap/agent-eye

macOS and Linux. Free and open source, MIT licence.

THE BOARD

This is the real board, running on made-up data. Click a card to open it, press / to search, right-click a card for its menu. On your machine it runs on 127.0.0.1, and Chrome or Edge can install it as an app with its own window.

WHAT IT DOES

  • {{sprite:scan:4}}

    Every session, found

    It reads the session files your agent already writes. Nothing to wrap, nothing to log by hand. New sessions show up on their own.

  • {{sprite:needs_you:4}}

    What needs you, on top

    Running, Needs you, Waiting on others, Paused, Done. A session stopped on a permission prompt or a question is the first card you see.

  • {{sprite:note:4}}

    State and next step

    One line on where each session stands and one on who acts next, plus its pull requests, commits and tickets. Read the board, skip the scrollback.

  • {{sprite:search:4}}

    Search all of it

    Titles, prompts, replies, PR links and folders. From the board, from the terminal (eye or Ctrl-G), or by asking your agent.

  • {{sprite:resume:4}}

    Back in one move

    Enter, or one click, resumes the session where you left it, or forks it. When your agent has already deleted an old transcript, agent-eye puts its own copy back first.

  • {{sprite:ideas:4}}

    Ideas wait as cards

    Park an idea with notes and a first prompt. Start it later as a real session, in the right folder, with one click.

HOW IT WORKS

YOUR AGENT

writes every session to disk

~/.claude · ~/.codex
{{sprite:arrow:4}}

AGENT-EYE

a small background scanner with a local index and archive copies

~/.agent-eye
{{sprite:arrow:4}}

  • BOARD

    in your browser

  • PICKER

    in your terminal

  • /EYE SKILL

    inside your agent

  1. It reads. Your agent keeps a file per session. agent-eye reads them, and a few hook events, to know what is running and what is waiting.
  2. It sorts. Simple rules place each session in a lane. Your agent writes the one-line state and next step, so the card says something useful.
  3. You act. Open the board, press Ctrl-G in the terminal, or ask your agent where you left off. Resume, fork, or mark it done.

INSTALL

Pick one. Each puts agent-eye on your PATH. Homebrew works on macOS and Linux. You need macOS 11 or newer, or Linux with glibc 2.35 or newer, and Claude Code or Codex CLI.

HOMEBREW

brew install maxipavlovic/tap/agent-eye

INSTALLER SCRIPT

curl -LsSf https://github.com/maxipavlovic/agent-eye/releases/latest/download/agent-eye-installer.sh | sh

CARGO

cargo install agent-eye
  1. Run agent-eye install. It adds the short name eye, the hooks, the background scanner and the /eye skill, and tells you what it did. agent-eye uninstall removes them.
  2. Run eye for the terminal picker. For the board, run eye board on, then eye board prints its address.

Read the docs for the keys, the settings and the API.

PRIVATE

Everything stays on your machine.

  • No account, no telemetry, no server of ours. The board listens on 127.0.0.1 only, behind a token.
  • Summaries use your agent’s own login and plan. For each one, a short excerpt of the session (with secrets masked) goes to your agent, the way the session already did. You can turn summaries off and keep everything else.
  • Open source under the MIT licence, so you can read every line that touches your sessions.

AGENTS

Claude Code and Codex CLI. Built for more.

agent-eye reads the files each agent already writes, so it works with the Claude Code and Codex CLI you already use. It follows the ones it finds on your machine. Those files are not a public API and can change; if one does, agent-eye may need an update.

Codex runs hooks only after you trust them once: open Codex and approve them with /hooks. The code keeps each agent behind one layer, so others such as Gemini CLI can be added, and any of them can be switched off.
